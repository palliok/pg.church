# Поклонная гора — бэкенд (Laravel 13 + Backpack 7)

Панель управления для сотрудников церкви и публичный API только для чтения,
из которого фронтенд (`../frontend`) берёт данные вместо моков.

- **Laravel 13**, PHP 8.4, **PostgreSQL 17**
- **Backpack CRUD 7** (бесплатная версия, тема Tabler) — панель по адресу `/admin`
- запускается в Docker: `php-fpm` + `nginx` + `postgres` (см. `../docker-compose.yml`)

## Запуск

Все команды выполняются из корня репозитория.

```bash
cp backend/.env.example backend/.env
docker compose up -d --build
docker compose exec app composer install
docker compose exec app php artisan key:generate
docker compose exec app php artisan storage:link
docker compose exec app php artisan migrate --seed
docker compose exec app php artisan basset:cache
```

После этого:

- панель управления — http://localhost:8300/admin
  (логин и пароль — `ADMIN_EMAIL` / `ADMIN_PASSWORD` из `backend/.env`, по умолчанию `admin@example.com` / `password`);
- API — http://localhost:8300/api/v1/...;
- PostgreSQL с хоста — `localhost:5437`, база `pgchurch`, пользователь `pgchurch`, пароль `secret`.

Порты меняются переменными окружения `APP_PORT` и `DB_FORWARD_PORT`
(при смене `APP_PORT` поправьте и `APP_URL` в `backend/.env`, иначе у панели не загрузятся стили).

`basset:cache` скачивает CSS и JS панели с CDN в `storage/app/public/basset`. Без этой команды
они скачиваются при первом открытии страниц, для чего контейнеру `app` нужен доступ в интернет.

## Тесты

```bash
docker compose exec app php artisan test
```

Тесты работают с отдельной базой `pgchurch_testing` в том же контейнере PostgreSQL
(создаётся при первом запуске из `docker/postgres/init`).

## Что есть в панели

| Раздел | Что редактируется |
| --- | --- |
| Расписание | события, проповеди к ним, гимны служения; календари для импорта событий |
| Сборник песен | песни и разделы сборника |
| Медиа | новости и блог, теги |
| Истории | истории-комиксы и их кадры |
| Служители | служители и дежурства по дням недели |
| Пожертвования | реквизиты (их может быть несколько, QR-код для каждых строится сам) и цели пожертвований |
| Настройки сайта | контакты, соцсети, ссылки на трансляцию и текст плашки «В эфире», предлагаемые суммы пожертвований |
| Администраторы | учётные записи панели |

Регистрация в панели закрыта: новых администраторов добавляет действующий администратор.

Панель работает на бесплатной версии Backpack; несколько возможностей PRO сделаны своими средствами:

- **фильтры над списками** событий, новостей, песен и кадров историй — `Admin\Concerns\HasListFilters`
  и `resources/views/admin/list_filters.blade.php`;
- **поиск в выпадающих списках** (гимны события, теги, событие проповеди) — поля `select_search`
  и `select_multiple_search` в `resources/views/vendor/backpack/crud/fields/`, на основе Tom Select
  (Apache-2.0, лежит в `resources/assets/vendor/tom-select`, без CDN);
- **превью обложек** новостей в списке и в форме;
- **кадры истории** перечислены на форме истории со ссылками на редактирование и добавление.
Каждый пользователь из таблицы `users` имеет полный доступ.

Набор настроек сайта задаётся в `database/seeders/SettingSeeder.php`; сидер можно запускать
повторно — сохранённые значения он не перезаписывает.

## API

Все ответы — JSON вида `{"data": ...}`. Имена полей повторяют объекты из
`frontend/src/data/mockData.js`, чтобы моки можно было заменить запросами без переделки страниц.

| Метод и адрес | Что отдаёт |
| --- | --- |
| `GET /api/v1/church` | контакты, соцсети, дежурства, ссылки на подписку на расписание |
| `GET /api/v1/live` | плашка «В эфире»: `isLive`, ссылки на трансляцию по площадкам, текст плашки |
| `POST`/`PUT`/`DELETE /api/v1/stream` | добавить, заменить или убрать ссылки на трансляцию (для Telegram-бота, нужен ключ — см. ниже) |
| `GET /api/v1/events` | расписание; параметры `from`, `to` (даты), `limit` |
| `GET /api/v1/events/{id}` | событие с проповедью и гимнами |
| `GET /api/v1/events/{id}/sermon` | конспект проповеди |
| `GET /api/v1/events.ics` | расписание календарём iCalendar — для подписки (`webcal://`) |
| `GET /api/v1/events/{id}.ics` | одно событие файлом `.ics` |
| `GET /api/v1/songs` | песни без текстов, но со строкой `line` — первой строкой песни, а при поиске строкой с совпадением; параметры `q` (название, строка, номер), `category` |
| `GET /api/v1/songs/{id}` | песня с текстом и аккордами, разобранными на секции |
| `GET /api/v1/song-categories` | разделы сборника |
| `GET /api/v1/posts` | новости и блог; параметры `type` (`news`, `blog`), `per_page`, `page` |
| `GET /api/v1/posts/{id}` | запись с полным текстом |
| `GET /api/v1/stories` | истории-комиксы без кадров |
| `GET /api/v1/stories/{slug}` | история с кадрами |
| `GET /api/v1/donation` | цели, суммы и список реквизитов (`accounts`), у каждых — ссылка на QR-код |
| `GET /api/v1/donation/accounts/{id}/qr.svg` | платёжный QR-код реквизитов; с `?download=1` — как файл |

Чем ответы отличаются от моков:

- идентификаторы числовые (`1`, а не `'e28'`);
- у события кроме готовых подписей (`day`, `mon`, `when`, `timeLabel`, `dowLabel`) есть `startsAt`
  в ISO 8601; `month` — от 1 до 12, `dow` — от 1 (понедельник) до 7 (воскресенье);
- проповедь вложена в событие полем `sermon` (вместо `preachers`), гимны — полем `hymns`;
- `/events` без параметров отдаёт события начиная с сегодняшнего дня;
- тексты песен отдаются только в `/songs/{id}` — полем `sections` (см. ниже), а не списком строк `lyrics`;
- содержимое пока только на русском: переводы на `en` и `ky` остаются во фронтенде.

## Тексты песен и аккорды

Текст песни хранится в колонке `songs.chordpro` в формате [ChordPro](https://www.chordpro.org) —
это обычный текст, который понимают OnSong, OpenSong, SongBook, MobileSheets и другие программы для музыкантов.

```
Куплет 1
[E]Свят, свят, свят Гос[A]подь Вседержи[E]тель,
Вся зем[C#m]ля пол[A]на славы Тво[H7]ей.

Припев
Те[A]бе поём хва[E]лу, Тебе одно[H7]му
```

- **Аккорды** стоят в квадратных скобках перед слогом, на который приходятся. Песня без аккордов — просто текст.
- **Секции** (куплет, припев, бридж) разделяются пустой строкой; заголовок — отдельная строка перед текстом
  («Куплет 1», «Припев:», «Бридж x2»). Заголовок без текста под ним означает повтор («Припев»).
  Понимаются и директивы ChordPro: `{start_of_chorus}` … `{end_of_chorus}` (кратко `{soc}` … `{eoc}`),
  `{chorus}`, `{comment: …}`; `{title}`, `{key}`, `{capo}` и прочие в текст не попадают.
- **Ноты** пишутся латиницей в немецкой системе, принятой в России: `H` — си, `B` — си-бемоль.
- **Вставка с сайтов.** Текст, где аккорды стоят отдельной строкой над словами, можно вставить в админке
  как есть: при сохранении аккорды переносятся в строку (`App\Support\ChordPro::normalize`).
- **Поиск.** Аккорды разрывают слова («Гос[A]подь»), поэтому при сохранении в колонку `songs.lyrics`
  записываются одни слова, и поиск по строке идёт по ней. Руками её менять не нужно.

API отдаёт текст уже разобранным (`App\Support\ChordPro::parse`), клиенту парсер не нужен:

```json
{
  "hasChords": true,
  "sections": [
    {
      "type": "verse",
      "label": "Куплет 1",
      "lines": [
        [
          { "chord": "E", "text": "Свят, свят, свят Гос" },
          { "chord": "A", "text": "подь Вседержи" },
          { "chord": "E", "text": "тель," }
        ]
      ]
    }
  ]
}
```

`type` — `verse`, `chorus`, `prechorus`, `bridge`, `intro`, `interlude`, `outro`, `tag` или `null`;
строка — список фрагментов: аккорд (или `null`) и текст до следующего аккорда.

## Реквизиты и QR-коды для пожертвований

Реквизитов может быть несколько (например, на уставную деятельность и на строительство) — раздел
«Пожертвования → Реквизиты и QR-коды». Картинку с QR-кодом загружать не нужно: сайт строит её сам
из реквизитов по ГОСТ Р 56042-2014 — это тот же формат, что у кода, который выдаёт банк, и его читают
приложения банков:

```
ST00012|Name=<получатель>|PersonalAcc=<расчётный счёт>|BankName=<банк>|BIC=<БИК>|CorrespAcc=<корр. счёт>|Purpose=<назначение>|Sum=0|PayeeINN=<ИНН>|KPP=<КПП>
```

Поменяли реквизиты в админке — поменялся и код. После изменения стоит отсканировать новый код
приложением банка и убедиться, что реквизиты подставились верно.

## Плашка «В эфире»

Плашка над шапкой сайта видна, пока в «Настройки сайта → Трансляция → Ссылки на трансляцию» есть хоть одна ссылка.
Ссылок может быть несколько — по одной на строке, на разных площадках (YouTube, VK Видео, Rutube, Telegram,
Одноклассники и другие): на плашке по кнопке на каждую. Площадка определяется по адресу ссылки
(`App\Support\StreamLinks`). Пустое поле — плашки нет. Открытые страницы сайта проверяют это раз в минуту.

Ссылки может ставить и убирать Telegram-бот: для этого в `.env` задаётся ключ `STREAM_API_TOKEN`
(длинная случайная строка, например `openssl rand -hex 32`), и тот же ключ отдаётся боту.
Без ключа на сервере адрес отключён.

```bash
# добавить ссылку; ссылка той же площадки заменяется (новый эфир на YouTube вместо прошлого)
curl -X POST https://<сайт>/api/v1/stream \
  -H "Authorization: Bearer $STREAM_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"url": "https://www.youtube.com/watch?v=..."}'

# заменить весь список ([] — убрать все)
curl -X PUT https://<сайт>/api/v1/stream \
  -H "Authorization: Bearer $STREAM_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"urls": ["https://www.youtube.com/watch?v=...", "https://vkvideo.ru/video-..."]}'

# убрать все ссылки (плашка скрывается) или только одной площадки: ?platform=youtube
curl -X DELETE https://<сайт>/api/v1/stream -H "Authorization: Bearer $STREAM_API_TOKEN"
```

Ответ — то же, что отдаёт `GET /api/v1/live`:
`{"data": {"isLive": true, "links": [{"platform": "youtube", "name": "YouTube", "url": "…"}], "text": "…"}}`.
Ключи площадок: `youtube`, `vk`, `rutube`, `telegram`, `ok`, `twitch`, `facebook`, `zoom`; для незнакомого
сайта — его домен. Ссылки должны начинаться с `http://` или `https://` (иначе 422); неверный ключ — 401;
не больше 30 запросов в минуту. Каждое изменение пишется в лог приложения.

## Календари

Расписание отдаётся в формате iCalendar (RFC 5545), который понимают Google Календарь, Apple Календарь,
Outlook и Яндекс Календарь.

**Посетителям.** На странице события кнопка «В календарь» предлагает Google Календарь, Outlook
и файл `.ics` (Apple, Яндекс и остальные). На странице расписания «Подписаться» добавляет всё
расписание как календарь, который сам обновляется (`/api/v1/events.ics`, по `webcal://`).
Ссылки берутся из API: поле `calendar` у события и `calendarFeed` в `/api/v1/church`.
Если у события не указано окончание, в календаре оно длится `EVENT_DURATION` минут (по умолчанию 90).
Страницы событий в календарях ведут на сайт по адресу из `SITE_URL`.

**Администраторам.** Раздел «Расписание → Календари для импорта»: вставьте ссылку на календарь
в формате iCal — где её взять в Google, Outlook, iCloud и Яндексе, подсказано в форме. Ссылка хранится
зашифрованной: у Google и iCloud она даёт доступ к календарю.

- Синхронизация идёт каждые 15 минут (сервис `scheduler` в docker-compose, команда `php artisan calendars:sync`),
  сразу после сохранения календаря и по кнопке «Синхронизировать».
- Загружаются события от 30 дней назад до года вперёд; повторяющиеся события разворачиваются в отдельные даты.
- Из календаря берутся название, описание, место и время — их нужно менять в календаре, при синхронизации они
  перезаписываются. Метка, гимны, трансляция, проповедь и публикация, заданные на сайте, сохраняются.
- Событие, удалённое или отменённое в календаре, удаляется с сайта; если к нему уже есть проповедь — только
  снимается с публикации. Личные события (`CLASS:PRIVATE`) на сайт не попадают.
- Серверу нужен доступ в интернет, чтобы скачивать календари.

## Перед выкладкой на сервер

- задать свои `APP_KEY`, `ADMIN_PASSWORD`, пароль базы; `APP_ENV=production`, `APP_DEBUG=false`;
- задать `APP_URL` (адрес API — на него ссылаются подписки на календарь) и `SITE_URL` (адрес сайта);
- задать `STREAM_API_TOKEN`, если ссылки на трансляцию будет ставить Telegram-бот;
- `docker/php/Dockerfile` рассчитан на разработку: код монтируется томом, а не копируется в образ.
